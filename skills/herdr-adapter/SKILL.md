# Hybrid Conductor: herdr adapter

herdrは実行基盤、このskillは共通の役割と実行操作を結ぶ薄い接続層。
CLIの操作マニュアルをここへ複製しない。**導入済みバイナリの `herdr --skill` が操作仕様の基準。**

## 接続前

最初に次を実行し、出力を省略せず読む。

```bash
herdr --skill
```

CLIがない、失敗する、出力を読めない場合は不足を報告し、操作構文を想像して進めない。
Web上の最新版や同梱コピーで導入版の仕様を代用しない。現在の出力に従って必要なhelpを取得する。
`HERDR_ENV=1` がない環境からセッションを操作しない。値を自分で設定して条件を偽装しない。
必要なら `scripts/bootstrap.py` で同じ `herdr --skill` の取得と環境確認を行える。
この補助はpaneを作成せず、agentを起動せず、セッションにも接続しない。
既に出力を読んだ同一実行中に、毎タスクで読み直す必要はない。バイナリ更新後は再取得する。

## 共通の役割をherdrへ渡す

1. 現在のcaller、作業場所、セッションを確認し、導入版skillに従ってCLIとserverの対応を確認する。
   存在するpaneやagentのIDは実際の応答から読む。表示順・例・agent種別からIDを作らない。
2. 有効な設定の `roles.<role>` からagent、model、effortを解決する。
   `agent` は実行CLIの選択（この版ではCodexまたはClaude Code）で、herdrのkind名は導入版helpから解決する。
   model/effortはnative CLIのhelpや設定表示でも確認する。APIで利用できても当該CLIで使えるとは限らない。
   `inherit` はCLI自身の既定を使う指示。mainのinheritはmainを変更しないという意味。
3. 導入版skillの手順で、利用可能なshell paneを確保してagentを起動する。
   起動の直前に [起動の準備とテンプレート](references/launch.md) を読む。
   **既定は現在のtab内・現在の作業ディレクトリ・フォーカス維持。** topologyを無断で拡張しない。
   paneとagentには同じ役割名（例: `hc-worker-core`）を付け、paneを別の役割に再利用するときは付け替える。
   設定の `allow_worktrees: true` または今回の明示許可がある場合だけ、合意した場所にworktreeを作れる。
   同一ディレクトリでは変更範囲を分け、競合する編集を直列化する。並列数はレイアウトと資源にも合わせる。
4. native model/effort引数を導入版の正式な方法で渡す。プロンプトにモデル名を書くだけで選択したことにしない。
   モデル文字列をshellへ無引用で埋め込まない。引数は配列または正しく引用された値として渡す。
   未対応の `max` を黙って `high` / `xhigh` に変えない。起動不可なら承認済みの設定変更を求める。
   権限もCLIの引数で渡す。reviewerなど読み取り専用の役割を書き込み可能な権限で起動しない。
5. 起動後、認識されたagentと要求したモデル・effortを照合し、実効値が取れれば記録する。
   推測値を実績値としない。取得不可ならunknownと明示し、指定を正式な引数で渡した証拠は残す。
   CLI自体のfallbackが起きた場合も変更を報告し、当初のモデルとして数えない。
6. 起動準備を確認してから、一意のタスクIDを付けた短い委任を送る。
   子にHybrid Conductor全体を再起動させない。今回の役割・対象・必要な方針だけを渡す。
   別CLI側にこのPluginが入っていると仮定せず、必要な方針を本文または読める絶対パスで渡す。

## 並列実行と結果回収

独立したタスクを各agentへ送ってから、導入版が提供する状態待機で回収する。
一件ごとに完了まで待ってから次を起動し、意図せず直列化しない。
同じagentへ複数の未完了タスクを重ねて送り、どの応答か分からなくしない。
完了回収と次の割り当ての前に、タスクIDと現在の応答を照合する。

待機APIのidle/doneなどは、タスク合格の証拠ではない。本文・成果物・実行した検証を確認する。
blockedは承認や質問を確認する。権限ダイアログを反射的に承認しない。
タイムアウトや接続エラーは「送信されていない」の証拠ではないため、状態と出力を読んでから再送を判断する。
待機のタイムアウトを、レビュー回数上限やタスクの機械的な打ち切りへ転用しない。

初回は短いテキスト報告を返させる。初期プロンプトから全agentにレポートファイル作成を要求しない。
出力を回収できない場合だけ、導入版skillに従って同じマシンの一時ファイルへ報告を書かせる。
コードやモックなど本来の成果物と、報告ファイルは区別する。

## レビューと後片付け

初回reviewerは実装者のセッションを使い回さず、新しい独立コンテキストで起動する。
共有作業ツリーでは対象への書き込みを止め、未追跡の成果物も含む対象を固定する。
修正後は同じreviewerを継続利用できる。交代時は指摘と判定の履歴を引き継ぐ。
ソース変更禁止の役割指示はsandboxではない。利用可能なCLI権限を用い、強制できない境界は明示する。

自分が作った資源と未回収の成果を記録する。後片付けでは無関係なpaneやagentを停止せず、ラベルも変更しない。
セッション・serverの停止、認証設定変更、リモート接続の追加は、このskillの通常操作に含めない。
v0.1は現在のローカルセッションが対象。別マシンの操作は対応範囲に含めない。
