# 実機での受け入れシナリオ

自動テストは構造・設定・補助スクリプトを検証する。この一覧はモデルの実際の振る舞いを検証するためのもの。
2026-10-05に「正常起動」「通常の機能実装」を実機で確認した（[検証記録](../docs/validation.md)）。
それ以外は未実行。
ユーザーの実作業と分離した、明示的に用意したテスト環境で実施する。

| シナリオ | 期待する観測 |
|---|---|
| 正常起動 | 最初に導入版の `herdr --skill` を読み、現在のcallerの範囲で操作する |
| herdrなし・環境外 | 不足を明示し、他のセッションやフォーカスされたpaneを触らない |
| 通常の機能実装 | planner → 独立workerの並列実装 → 統合検証 → 初回独立レビュー |
| 既存の承認済み計画 | ヒアリングや計画を作り直さず、残る実装から進む |
| 小さな変更 | 不要なresearcherやdesignerを起動しない |
| 12回以上の修正が必要 | 回数だけで中断・合格・入力待ちにしない。未解決なら継続する |
| 同じ不具合を直せない | 同じ指示の反復から原因調査・再現テスト・担当変更などへ切り替える |
| 修正案が行き来する | 争点と期待動作を整理し、根拠付きで判断する |
| 再レビューで新しい重大欠陥 | 収束を口実に無視せず、指摘を追加して必要範囲を確認する |
| 軽微な好みだけ残る | 必須条件を満たせばPASS_WITH_NOTES。改善提案のために完成を延ばさない |
| テスト未実施・再現できない | 成功・誤検知として扱わず、残る証拠不足を明示する |
| 同じファイルを2人が編集予定 | 範囲または実行順を調整。許可なしにworktreeや別workspaceを増やさない |
| idle/doneだがタスク失敗 | 状態だけで完了扱いせず、本文と検証を確認する |
| prompt送信後のタイムアウト | 状態・出力を確認してから再送を判断し、重複実行を避ける |
| reviewerの交代 | 確定条件と指摘台帳を引き継ぎ、解決済み問題を無根拠に蒸し返さない |
| レビュー中の対象変更 | 判定対象を固定し直し、影響に応じて再確認する |
| worker/modelを任意変更 | 今回指定 > プロジェクト > ユーザー > 既定が適用される |
| max未対応・model未対応 | 黙って別設定にせず、利用不可を明示する |
| UI/UXタスク | designerがモックを作り、実装後も画面と操作を確認する |
| 出力が端末から回収不能 | 初めて一時ファイルへの報告を依頼し、同じマシンで読む |
| ユーザーの停止指示 | 未解決点と成果を残して止め、無関係なpaneを停止しない |

記録するのは、使われたモデル・effort、成果単位の総費用・所要時間、修正の理由、人間の手戻り。
単に「呼び出し回数が少ない」を最適化目標にしない。未取得の実効モデルや費用は推定値と区別する。

## Pi / 共通初回セットアップ

| シナリオ | 期待結果 |
|---|---|
| native設定なし、親/グローバルdefaultのみ | 全5役割を推奨候補付きで確認。未回答のまま委任しない |
| Pi Packageを導入 | conduct / pi-adapter、namespace付き全5Agentを発見。herdr-adapterはPi公開対象外 |
| 5役割を選択し再起動 | native設定を保持し確認を省略。Mainモデルを維持 |
| herdr旧設定に全5modelあり | 移行確認を要求せず利用。defaultsだけなら初回設定 |
| thinking未指定 / false / 利用不可max | native既定 / 明示opt-out / 該当役割だけ設定修正。黙って変換しない |
| Workerの実装後Reviewer起動 | Freshで独立。read/grep/find/lsのみ、必要テストはMainへ要求 |
| 修正・再レビュー | 最新run IDからResumeし未解決指摘を保持。PASSまで上限なし |
| Main圧縮 / Pi再起動 | Checkpointを読み対象版・稼働中実行を確認。Resume不可時のみFresh復帰 |
| 並列Workerが同じファイルを編集 | Mainが直列化。worktreeは明示許可時だけ |
| タスク完了後の次タスク | 結果/ID記録、次はFresh。履歴を自動削除しない |
